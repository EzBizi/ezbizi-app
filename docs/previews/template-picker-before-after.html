Two causes, and the control owned one of them. The screen was handing the picker "name — whole body" as one string, so there was nothing to lay out — the name and the body were the same sentence. That is fixed where it is built. But the picker itself would wrap any long label to any height, so the next screen with a long line got the same wall: the closed field has cut long text off since the day it was written and the open list never did. Now the name gets one line, the body gets two, and the rows are ruled apart. Typing a word from the body still finds the template.
The same fix reached a second screen you have not seen yet — the building-code picker in the Inspection builder was doing the same thing, a code and its title crammed into one line so a long title pushed the code off the end.
