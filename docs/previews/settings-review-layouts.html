Settings: the whole tab, reviewed

Jose, 2026-10-19: "review all the Integration screen, and each individual integration screen" and "review the Entire Settings tab". Every name here is invented.

What's wrong today:

  • The six tabs don't match each other:
    • three have a header and three don't;
    • each switches to its phone layout at a different width (five widths in all);
    • empty and error states come in five styles, and Integrations and Activity have no Try again;
    • a button you can't use is greyed out with a reason in Organization and Roles, and simply hidden in Integrations.
  • "Settings › Settings" says the same word twice.
  • Every integration opens the same shared screen:
    • only Google Workspace can be disconnected, and it doesn't ask "are you sure";
    • with nothing connected, it says "Connect it in Leads" twice, under the title "Connect another";
    • Twilio, WhatsApp and the email sending server aren't listed at all;
    • Facebook appears as two separate entries;
    • the forms use developer terms like "JWT", "v1 secret" and "Base id".
  • Activity shows the server's internal action codes, and rows can't be opened.

1 One pattern for every tab, one page per service RECOMMENDED

Every tab follows the same rules:

  • the same header: a title, one line saying what the tab is for, and its main action on the right;
  • one width at which every tab switches to its phone layout;
  • one empty state, and one error state that always has Try again;
  • a button you can't use stays visible, greyed out, with the reason.

The Settings sub tab is renamed Preferences, so the path no longer says "Settings › Settings". Integrations lists every service, including Twilio, WhatsApp, the sending server and RingCentral, with Facebook as one entry.

Each service's page has the same three parts, top to bottom:

  1. What it's for, in one line.
  2. Connected: one row per organization, company or branch. Each row shows when it last synced and the last error, with Edit and Disconnect; Disconnect asks once more before it acts.
  3. Connect: the fields that service needs and where to find them in it, plus a choice of how to connect when the service offers one (as Workiz does).

The forms use plain words. A service that connects from another module shows one button to go there, not three.
