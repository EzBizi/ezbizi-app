API activity · what an AI or a script did with a key

From MCP / API, for Jose's ask of 2026-10-07: "we should probably have an MCP-API log to records the actions", "add all the logging to the MCP-API from now on", "so changes can be reverted if needed". Every request made with an API key is now recorded: who, which key, what it read or changed, and for a change, what was sent and what it replaced.

Data: GET /api-keys/activity, newest first, 200 at a time, filtered by key or (for administrators) by person. Each row holds when, who, which key, the request, its result, whether it came through the MCP or the API, and for a change the body sent and the record before it. A key's owner sees their own keys; an administrator sees the whole organization. In every option: each row is worded as Read, Created, Changed or Deleted, not GET/POST. Changes only is on by default, because reads are most of the traffic and none of the risk. A change opens to show each field the way it was and the way it was set.

1Last few under each key in Your account; the whole organization in Settings › API activity Recommended

Your account: each key in the API keys card gets an Activity link, which opens its last few changes under it, with "Show all" for the rest. Administrators: a new API activity tab in Settings, after Roles & permissions, where the key kinds are decided. It is one table with Person, Key and Changes only filters. Click a change to see each field before and after. Put it back undoes one change, as Jose's "so changes can be reverted" asks. It needs one more server action, so say if you want it. Why: a person checks their own key where they made it, and an administrator gets one place for everyone's.
