Automations › Then: steps anyone can set up

Jose (2026-10-22): "how is the user supposed to even know the fields at all … regular users will have no knowledge of how status or fields are named inside the app." I checked every step against every trigger. The main problems:

  • Many steps are offered for events they can't work on.
  • "Change the status" has no box to pick the status.
  • "Set to" is free text.
  • Raw field names appear as Details.

Every name and value here is invented.

1 Only steps that fit, pickers for every value, and a sentence saying what the step does RECOMMENDED

  • Choosing a step: the list is grouped as "For this job", "Send a message", "Tell the team" and "Elsewhere". It only lists steps that work for this event.
    • A step that isn't set up yet is greyed out, with the reason ("No number that can text in Springfield · Set it up").
    • Steps that never apply aren't listed.
  • "Update a detail":
    • first, which detail, from a list in plain words (Status, Sub-status, Job type, Tags, Scheduled for, Amount);
    • then the value, with a control that fits it: a list of the company's own statuses, a date picker, a dollar amount, a switch, or tag chips.
  • "Change the status" becomes the same list of statuses, so it can finally be saved.
  • Messages: placeholders are chips with plain names ("Customer's first name"), added from a list. The preview fills them with the last event's real values.
  • Each step ends with a green sentence saying what it will do: "Sets the job's status to Done, pending approval."

2 Ready-made recipes for each event

Above the step list there are 3 to 5 recipes for this event, such as "Text the customer that the job is done" or "Move to Done, pending approval". Each one fills in the steps for you to adjust. It's the fastest start, but it still needs option 1's pickers underneath.
