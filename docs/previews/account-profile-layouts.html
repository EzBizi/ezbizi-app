Your account — layouts

A data defect, not a layout one — “You can act on” repeats itself The list currently reads: Connecticut, DMV, Georgia, Illinois, New Jersey, Ohio, Texas, Washington, Nationwide, Connecticut, DMV, Connecticut, Connecticut, Florida. Connecticut four times and DMV twice — fourteen entries for ten places. Almost certainly one row per grant rather than one per place, so somebody with several roles touching Connecticut is shown Connecticut several times. It reads as a rendering fault and it is a query that needs a DISTINCT — and it matters more than it looks, because this list is the answer to “where am I allowed to work”, and a list that repeats itself is one nobody trusts the rest of. Every layout here de-duplicates and shows the count.
Three things the current screen does that the layouts undo 1 · A field is as wide as the card, not as wide as its content. “Jose” sits in a box about 700px across; the whole first card is one column stretched to 1650px. A field that wide stops looking like a field for a first name and starts looking like a mistake — and the eye has to travel the full width to find the next label. 2 · Two kinds of information are dressed the same and behave differently. Name, phone and address are editable. Email, Role, Organization and “You can act on” are facts about your account that you cannot change here — but they sit in the same card, under the same heading, above the same Save button. The Save applies to some of what is above it and not the rest, and nothing on screen says which. 3 · Gender is two controls for one value — a text box reading “Male”, and four chips underneath. Whichever is authoritative, the other is a second way to set the same thing.
One rule this screen is currently on the wrong side of The date of birth has a calendar icon. If that opens a date picker, it is a dialog — and this codebase has none: Hours was explicitly built with a masked text field rather than a time picker for exactly this reason (8910b88), and screens written since assert findsNothing for showDialog. A date of birth is also the worst possible case for a picker: it is thirty years ago and nobody wants to page back through 360 months. All three layouts use a masked field — you type it, the same way Hours works. Otherwise unchanged: Appearance, Two-factor and Password keep their own cards and their own controls, and the footer rule holds — a card that can be saved has a footer, a card that cannot does not.
