The whole problem in one sentence: three marks, and the dot is taken A row now has to say three independent things at once, and any of the eight combinations can occur:
MarkWhoseMeans
unreadyours aloneyou have not opened it since the last message
unrepliedeveryone'sthey spoke last — already the dot
starredeveryone'ssomebody marked it
A second dot is not available, and neither is a coloured bar down the leading edge. So the answer is to use a different CHANNEL, not a second badge. Unread becomes weight — the name and the preview go bold. It is the convention every mail client has taught for thirty years, it costs no width at all, it cannot be mistaken for the dot, and it composes: a row can be bold AND dotted AND starred and still read as three separate facts rather than as clutter. Layouts 2 and 3 spend a badge and a tint on it instead so the comparison is visible rather than asserted.
Verified on main before drawing — all of it is already there 2026_09_08_233000_add_triage_marks_to_leads.php adds starred_at, note and the lead_reads table. The list joins lead_reads.read_at and computes is_unread as no mark, or a message newer than the mark. Routes exist for POST leads/{id}/read, POST leads/read-all and PATCH leads/{id}. Unread and Starred come off the struck-through list. All three filters have data behind them now, so all three are drawn. They are independent toggles that narrow together: Unread + Starred means both, not either. That is the only reading that makes "starred things I have not read" expressible, which is the one combination somebody actually wants.
A gap in the note, and it is worth deciding before it ships The migration says star and note are “facts about the lead, shared by everybody who can see it”, and note is a single text column with no author and no timestamp. So a note reads “Called back, no answer” and cannot say who or when. Two people can also overwrite each other silently — last write wins, with nothing on screen to show it happened. At one user that is invisible; A-1 Chimney has several. Every layout below therefore shows the note as ONE shared line, not as a conversation, and none of them pretends to attribute it. If Jose wants "Maya, 2h ago" the field needs an author and an edited-at, which is a small change to the Leads module — I have not asked for it because a shared scratchpad may be exactly what he means.
