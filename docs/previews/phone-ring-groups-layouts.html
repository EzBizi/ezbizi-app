Phone › Ring groups — layouts

Read from ring_groups_pane.dart “A group is who a line rings.” Each group has a name, a phone account, a strategy — Everyone at once or One at a time — a ring timeout, and members. The timeout is capped and the copy already says why: “Twilio hangs up a browser call at 60 seconds, so it cannot ring longer.” Empty state exists and is good: “No groups yet. Without one, a call goes straight to voicemail.” Today the list and the draft form share one ListView (:309), so the form sits below the groups. Pane pattern is layout 1, approved.
The finding: being in a group and being reachable are different things, and only one is drawn The pane's own sentence is the whole problem — “Someone only rings if they are signed in with Phone open and not on Do not disturb.” It is said once, at the top, as prose, and then the member list shows names. So a group with four people can ring nobody and look completely fine. Phone confirmed the server already knows: DialPlan::batches() is a three-condition check, and a group whose every member sits at Do Not Disturb comes back empty — “has nobody available to ring, so every call goes to voicemail.” That is the state that answers no calls while looking perfectly configured, and it is the exact shape this module has been fixing all week. Every layout here draws reachability per member and tallies it for the group. Not as a warning bolted on top — as the column the list is about. Membership is what you edit; reachability is what you came to find out.
One thing I need you to rule on Reachability is a live fact and this is a settings screen. Somebody signs out and the group's tally changes without anybody editing anything — so the pane can show a green “3 of 4 can be reached” that is stale within a minute, which is a smaller version of the honesty problem already settled on Trust and Scheduling. Every layout therefore timestamps it (“as of a few seconds ago”) rather than implying live presence, because there is no realtime transport here either. If you would rather the pane not show live state at all and stay purely a configuration screen, say so — it is defensible, and it costs the one thing the screen is currently worst at.
