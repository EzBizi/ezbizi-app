Scheduling · Locations: where every branch is, which one is closest, and who to call

Jovanni Martin (A1-Group, 2026-10-01), suggestion 0080: "Add a general information tab that displays company addresses with a feature that shows the closest location to the inputed address similar to the a-1 site as well as contact info for newbie dispatchers". Jose: "Implement".

Where it lives: Scheduling, a Locations tab beside Availability · Schedule · Overbooking · Settings. A dispatcher asks "who covers this address" while booking, and the answer is a branch whose availability is one tab away. Every option offers Check availability on the result.

What exists today. The branches are already data: web_locations (the store locator and branch pages the websites draw) hold each branch's address, phone, email, map link and coordinates. Typing an address can be geocoded with the same free lookup the app's address boxes use (Photon, OpenStreetMap). It already returns coordinates, which the client currently throws away. Scheduling's service areas know which ZIPs each area covers. New in every option: GET /scheduling/locations (the branch list) and GET /scheduling/locations/nearest?q=: geocode, then straight-line miles to every branch, plus the area whose ZIPs include it. new marks what the server does not send today.

Distance, not drive time. Straight-line miles cost nothing. Drive time needs a paid routing service (Google), or a public one with tight limits, so no option shows it. If a dispatcher's question is "who serves this ZIP", the service area answers it better than miles, and every option says so first when the two disagree.

1Look up first, then the list and one branch beside it Recommended

The tab opens on one box: a customer's address or ZIP. The answer is a strip of three, the closest branch large and two runners-up small. Below, every branch grouped by state, and the one picked, with its phones, map link and the notes for new dispatchers. Why: the lookup is the question asked twenty times a day; the directory is the one asked once.

Data: the two reads above, and per company a short "For new dispatchers" note new that holders of scheduling.settings edit in Scheduling › Settings (who to call, extensions, house rules). The branch phones and emails are the published ones.

2The map: every branch a pin, the answer drawn on it

A map fills the tab. The lookup and its three answers float over the top-left, the typed address is a red pin, and the closest branch is green. Clicking a pin opens that branch's card in the same place. The notes for new dispatchers sit behind a Who to call button.

Data: the same two reads and the same note new, plus map tiles. The app already draws maps with flutter_map (Field's routes). Public OpenStreetMap tiles allow light use with credit, which suits a few dispatchers but not every office all day. Heavier use needs a paid tile service.

3One table of every branch; a lookup adds Miles and sorts by it

A directory first: one row per branch with its address, phone and what it serves. Typing an address adds a Miles column, sorts the table by it, and marks the branch that serves the ZIP. The notes for new dispatchers are a banner above the table, folded after the first visit.

Data: the same two reads and the same note new. nearest answers miles for every branch rather than the top three.
