App sidebar — it does not scroll

The cause, from main.dart:1695 _rail() returns a Flutter NavigationRail, and a NavigationRail lays its destinations out in a Column — it has no scrolling of its own. It is wrapped in an Expanded, so when there are more destinations than fit, the column overflows its box and the items render over the Settings / Development tail below. That is exactly the collision in your screenshots: Inventory through the divider, Services on top of Settings, Development on top of Automations. It is height, not width, and it has a threshold. Sixteen destinations plus the tail and the version stamp need roughly 780px of sidebar. Anything shorter overlaps, and nothing warns:

Already decided, not in this gallery The tail is deliberately a different kind of thing — the code says so: places you go to change how the work behaves, rather than places you go to do it. Its divider is inset to about 70% on purpose, so it reads as a break within one list rather than as the bottom of the sidebar. The version stamp only appears when expanded, because half a build id is worse than none. None of that changes here.
The real question is what is allowed to scroll away Settings and Development must stay reachable — the code comment already says hiding the tail would make them unreachable, and that reasoning holds. So the choice is between scrolling the destinations under a pinned tail, or scrolling everything and accepting that Settings can leave the screen. A NavigationRail cannot simply be made scrollable, so whichever wins is a small structural change: wrap it in a scroll view with a minimum height so it still fills the column when there is room, or replace it with a list built from the same destination data. Either is a Phone-module-sized change, not a rewrite.

Pick a number. 1 is my recommendation. Windows are drawn at 800px tall — a common laptop, and where this is worst.
