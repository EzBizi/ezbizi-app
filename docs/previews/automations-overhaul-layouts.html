Automations · an overhaul

Jose 2026-10-09: "take a look at the Automations Tab and improve it… it's one of the screens we haven't been paying attention to and could use an ui-ux overhaul." Today each rule is a card with its name, a red "Off" chip beside an off switch (it reads as an error), "Everywhere", and a line like "When Jobs › Created · version — · 0 runs". Nothing says what the rule does, when it last ran, or whether that worked. Tapping a card does nothing, so everything sits in a ⋮ menu where "Run it now for real" is next to "Test against a real event". "New automation" and a "Build" tab lead to the same place. The builder is one long form with numbered steps, written for a developer in places ("…before the engine stops the cascade", "Rules are yours — they never need a new release"), and testing a rule only exists in the list's menu. Every name below is invented.

In every option: every rule reads as a sentence: "When a job is booked → text the office", using the event's and the steps' own names. The on/off switch is the only status. "Off" is grey, not red, and "Needs attention" shows only when a rule was switched off by EzBizi or its last run failed. Each rule shows its last run (time and whether it worked) and its runs this week. The "Build" tab goes, so New automation is the one way in. In the builder, testing sits next to Save ("Try it on a recent event"), and "Run it now for real" moves inside the rule, away from Test, with its confirm. The help text is rewritten for users. Version history stays, behind a "History" link. Nothing changes on the server except one field each rule already has the data for: last run.

1Rules as sentences, opened beside the list, built as When → Only if → Then blocks Recommended

Cards across, as you asked on 2026-09-22, now grouped by module (Jobs, Customers, Leads…) with a search box and All / On / Off / Needs attention. Clicking a rule opens it in a side panel: the sentence, its recent runs, and Edit, Test, Copy, Run now and Delete. The builder is three connected blocks, When, Only if and Then, each in plain words, with the name and Save in a bar at the top and Test beside Save. Why: you see what every rule does at a glance, the next step is one click instead of a hidden menu, and the builder reads like the sentence it makes.

2One table, the rule opens in a panel

A table: name, When, Then, last run, runs this week, and the switch, sortable and searchable. Clicking a row opens the whole builder in a wide side panel, so the list stays behind it. Why: the densest view, good once there are dozens of rules. But the sentences get cut to fit the columns, and the builder is squeezed into a panel.

3Ideas to start from, and a step-by-step builder

Under your rules is a row of ready-made ideas ("Text the office when a job is booked", "Ask for a review after a job", "Remind a customer the day before"), each one click to start. The builder asks one question per screen: When? Only if? Then? Name it. Why: the easiest for someone who has never built one, and the ideas show what is possible. But it's slower to change one thing, and going back a step is a detour.
