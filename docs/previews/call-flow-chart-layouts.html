Call flow, as a chart — pick one desktop and one mobile

Jose: “more graphic / Call Flowchart / a graphic view, where it shows the current state and separates into nodes like n8n / from left to right or up to down / and begins with Caller ---- (what happens)”. A new tab under Communication › Settings, beside the existing Call Flow pane rather than replacing it. Read-only — he said shows me, and an editable canvas is a different and much larger thing.

The picture is not what earns this screen. The two states are. Phone built the data and named them, and they are the whole argument: dead — a caller can reach it and nothing useful happens, an option pointing at a number nobody set, a ring group with nobody in it. skipped — configured and never reached at all: callers sail past and hear nothing, nobody complains because the caller does not know they missed a menu and the owner does not know theirs is skipped. A flowchart that draws a dead branch identically to a live one is prettier than the list and less useful, so every option below is judged on whether you can see those two without reading node by node — which is why each carries a count at the top.

Facts the layout may rely on, measured rather than assumed (TwimlRenderer::graph(), and a test that sabotage-checks): exactly one entry node, always caller; every node reachable from it and no edge dangling, so no defensive drawing for orphans; and it CAN cycle — queue → answer → queue and a “play the menu again” key are real, so a naive walk loops and a layered layout needs a back-edge that is drawn rather than followed. Six nodes without a menu, about eleven with a four-option one: small enough that nothing here needs virtualising. One graph per line, and a company can have thirteen, so every option carries the line picker the existing pane already uses.
