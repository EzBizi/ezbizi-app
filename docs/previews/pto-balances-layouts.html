Jose approved it 2026-09-17: “PTO Balances is good we should add that to Human Resources Tab”. It came from a real production suggestion — Toula Elwell at A1-Group, 2026-09-08, her spelling:

“a part for us where we can see howq much paidf pto we all have and when it can be used”

There are two asks in that sentence and the second is the hard one. “we ALL have” is a view across people, not self-service. “when it can be USED” is a waiting period, not a number — so on a screen called “balances”, the date is often the answer and the number is the decoration.

⚠ THE EMPTY STATE IS THE COMMON STATE, which is unusual and shapes every option here. HR measured production: exactly one of eleven contract templates mentions PTO at all, the other ten are silent. So “this organization has not set up paid time off” is probably the FIRST thing most people ever see on this screen — not an edge case to tuck away. (Their measurement of tenant data, relayed; I verified the models and the employment-events migration they name, not the eleven.) And the remedy belongs to whoever can edit contract templates, which is not most of the people looking, so state A must not be a button that does nothing for the reader.

Use the state switcher. Every layout is drawn in all five, because a layout that only reads well at “6 days available” is a layout for the rarest case.

⚠ STATE A IS ALL-OR-NOTHING, which corrected an argument I had already written down. All four PTO settings are organization-scoped, so “no policy” empties every row at once and can never be one person’s state beside somebody else’s. Not checkable from here — it is HR’s settings block rather than a tenant row, and not on main yet — so it is their measurement, relayed. It strengthens the recommendation rather than weakening it: option 2’s advantage was the mixed-state reading, and a third of that mix turns out to be impossible.

⚠ TWO COPY DEFECTS, BOTH OF THEM “A REMEDY THAT DOES NOT REMEDY”, AND THE SECOND IS THE DANGEROUS ONE.

State A used to say the policy is added to a contract template. HR caught it: PTO is an organization setting — pto.enabled, pto.days_per_year, pto.waiting_days, pto.carry_over — and a contract template has no field for it. An owner following my sentence would edit a template, publish a version, and the screen would still say “not set up”. (Verified from here: SettingRegistry does carry a Human Resources section.)

State D used to say “somebody in HR can add it”, and that one is worse, because the nearest thing to it lies. I went to check the remedy rather than repeat the mistake, and there is no way to record a start date that already happened: the only two writers of a started employment event are an is_active toggle and an invitation being accepted, and both stamp now(). So the only action resembling my advice — deactivating somebody and reactivating them — would stamp today, manufacture a confidently wrong eligibility date, and fire an activation notification on the way past. The copy now explains why it is unanswerable instead of pointing at a door.

And B said “your contract makes these available after three months”. EzBizi cannot read anybody’s contract; it knows the setting. It now says 90 days, taken from the setting, so changing the setting to sixty cannot leave the sentence claiming three months.

Where the feature leans next, worth drawing for now rather than redrawing later. A-1’s own paperwork is per-ROLE rather than per-company — that is what “one of eleven” means, and the one is Project Manager. So a per-person override on top of the organization default is very likely the next thing this needs, and then a roster genuinely does show six days beside zero beside two. Option 3’s table absorbs that without moving; a card wall would want re-reading.

Room is reserved for a number that does not exist yet. Nothing in EzBizi records a day off — HR measured that too — so whether a balance can say “2 taken” is undecided and sits between Scheduling and HR. Every option keeps the line for it, so the answer arriving does not move the layout. Same trick as the invitation strip leaving room for bounced.
