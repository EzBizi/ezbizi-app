App sidebar — finding a module

Context Sixteen destinations today and growing — Scheduling and Training are both mid-build, and Messaging is declared. Scrolling was just approved (ec25e74) and fixes the list does not fit. This is the other half: I cannot find the one I want. Scrolling makes a long list reachable; it does not make it findable. The sidebar is also the only navigation in the app, so a module you cannot find is a module you cannot open.
The obvious answer is unavailable here, and that is not a small detail Every app you would compare this to solves it with a command palette — ⌘K, a floating overlay, type and jump. EzBizi has no modals. The rule is stated in StartUp.md in as many words, five AlertDialogs were removed to enforce it, and every Tasks screen now asserts findsNothing for it. A palette is a dialog. Dimmed backdrop, traps focus, closes on Escape — it is the thing the rule forbids, wearing a keyboard shortcut. So it is not in this gallery, and I am naming it rather than quietly omitting it: if you want a palette, that is a decision to change the no-modals rule, and it should be made as that rather than arrived at as a side effect of wanting search. Everything here therefore searches IN the sidebar, which turns out to be a better fit anyway — the list is already vertical, already scrollable, and already where your eye is.
The one thing that decides this, and it is about the collapsed rail The sidebar collapses to a 74px icon strip, where a text field does not fit at all. Layout 1 shows a search icon that expands the sidebar when tapped; layout 2 keeps the field permanently and simply has none when collapsed; layout 3 avoids the question by never taking vertical space in the first place. Search should not need the mouse. All three focus on / — a single key, already the convention, and unlike ⌘K it carries no expectation of an overlay. Typing filters as you go, ↑↓ moves, Enter opens, Esc clears and restores the full list.

Pick a number. 1 is my recommendation. Sidebars drawn at their real width, in a short window so the interaction with scrolling is visible.
