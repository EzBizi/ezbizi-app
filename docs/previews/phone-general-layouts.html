Read from general_pane.dart General is what answers a call, and what it does on the way. Its own copy says the settings are “checked in this order — the first usable one wins”: hours, then the IVR menu, then the ring group, then a fallback number. Below that sit the voicemail greeting, call recording and the consent announcement. General is deliberately the form and Call flow is the report of what that form did — the code comment says so, and they are adjacent in the rail for that reason. Pane pattern is layout 1, approved. Empty state already exists and is kept: “No lines yet. Import or buy one on the Numbers screen.”
The finding: this pane describes a chain and draws a list “Checked in this order — the first usable one wins” is a caption above four unrelated dropdowns. Nothing on screen shows that the menu is tried only if hours say open, or that the ring group is reached only if no menu key answers, or what happens when all of them come up empty. The user assembles the pipeline in their head from four labels, and the pane's own sentence is the only thing telling them there is a pipeline at all. Two of the steps can silently do nothing, and the copy already knows it: “Skipped automatically if the menu has no usable step”, and “Nobody — every call goes to voicemail”. Those are the states worth drawing, because a menu that is configured but skipped is exactly the “it saved, it displayed, it did nothing” shape this module has been fixing all week. Layout 1 draws a skipped step as skipped. One thing I have deliberately NOT done: merge in Call flow. It would be easy to show the resulting path here and make Call flow redundant, and the code separates form from report on purpose. Layout 3 shows a preview alongside instead, which is the honest middle — judge whether that is useful or whether it just duplicates the neighbouring section.
