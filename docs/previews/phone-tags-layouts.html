Phone › Tags — layouts

Read from tags_pane.dart, not from a brief A tag is what a call was about — whoever answers picks one when the call ends, and reports count by them. A tag has a name, a colour from a fixed set of eight (customer-chosen but validated, so it stays readable on both light and dark surfaces), and a count of the calls it is on. Adding is a name field plus a button, wrapped in Refused so a role without phone.edit gets the server's sentence rather than a dead control. Pane pattern is layout 1, already approved. No modals, colours from theme.dart, 375px is a floor.
The state that makes this pane interesting, and the one every layout has to protect Retired is not deleted, and the existing copy says so better than most of this app: “Still naming the calls they were used on. Not offered any more.” A retired tag keeps its history and stops being offered at the end of a call — so a design that greys it out like a disabled row, or hides it, breaks the one thing somebody needs to understand before they retire anything. All three layouts keep retired tags present, legible, and counted, with “Offer again” on each. The call count is the curation signal and today it is a caption. “On 412 calls” and “Not used yet” are the same size and weight, so the pane cannot answer the question people actually open it with — which of these are dead weight? Layouts 2 and 3 promote usage to something you can scan; layout 1 keeps it quiet on purpose. That is the real choice here, not the arrangement. Tags also has no empty-state problem to solve — its existing empty copy already explains the consequence (“Until there is at least one, a call cannot be said to…”), which is more than most panes do. All three keep it.

Pick a number. 2 is my recommendation. 4 is the recommendation at 375px.
