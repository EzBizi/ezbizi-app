Module page header — one title, one size, one place

Six numbered layouts: 1–3 desktop, 4–6 mobile. The mobile ones are drawn for a phone rather than being the desktop header narrowed, so picking a desktop number does not pick a mobile one. Answer with one from each half.

What I measured in the code, not in the screenshots Sixteen screens render the shared tab row (TabBarLike). Exactly one of the sixteen prints the module’s name. It does it with a hard-coded TextStyle(fontSize: 25, fontWeight: w700) — a number typed into the screen, not a style from the theme. The other fifteen print nothing, so the page never says which module you are in. And the reason the headings that DO exist look unrelated to each other: theme.dart defines four text styles — headlineMedium 28/w800, titleMedium 16/w600, bodyMedium 14, labelSmall 11/w700. The app asks for three more that are not among them: titleSmall, headlineSmall and titleLarge. And a missing slot does not fall back to Material. ThemeData does not merge Material's typography in behind that map. An unlisted slot arrives as a TextStyle carrying a colour and nothing else — fontSize: null, fontWeight: null — so every call site renders at whatever size and weight the surrounding text happens to have. 109 call sites, and titleSmall is 93 of them on its own: ninety-three places that meant “a small heading” have been drawing ordinary body text in slightly darker ink. That is not a styling preference that drifted. Three of the six heading slots this app uses were never filled in.

So a page title today is one of several sizes at several weights, and on fifteen screens out of sixteen it is not there. Corrected after the build, 2026-09-01. This block first said the two undefined slots were getting “Material's defaults, 24px and 22px at weight 400”, and listed only two of them. Both wrong: nothing falls back, and titleSmall — the largest by far at 93 call sites — was missing from the count because the grep behind the table only looked for the two slots I had already noticed. The test now in theme_conventions_test.dart is what found the third, by checking every slot the app asks for rather than the ones somebody remembered.
The decision each layout is really making: which name is the title? Two names compete. The module — Human Resources — and the pane — “At a glance”. Today Scheduling and HR print only the pane name, Tasks prints only the module name, and most print neither. My reading, and every layout below is built on it: the module name is the title. The tab row is already telling you which pane you are in, and it is highlighted while it does it. So a separate “At a glance” heading directly beneath a lit-up “Dashboard” chip is the same fact twice. Which means the header is close to free. It does not add a row — it replaces the pane heading that is already there. That matters most on the phone, where the sidebar is a drawer and nothing on screen names the module at all until you open it.
