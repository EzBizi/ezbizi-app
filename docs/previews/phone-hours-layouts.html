Phone › Hours — layouts

Read from hours_pane.dart, with a constraint from the Phone session “When a line is open. A line with no hours is always open.” Hours belong to a phone account; a line points at a set. The editor has a name, a clock (“Clock these hours run on”), the week, and a separate list of days it is closed anyway — “Holidays and one-offs. These beat the week above.” There is NO time picker and there must not be one. A picker is a dialog and this codebase has no modals, so times are a masked field, validated as real times, from-before-to, equal refused (Phone, 8910b88). Every layout here uses the mask. Empty state exists and is kept: “No hours set yet. Every line answers around the clock until you set some.”
Two things this pane already gets right, which the redesign must not lose 1 · “A day with no times is closed, and says so.” Absence means closed — the same rule Scheduling settled, where closing a day deletes rows rather than writing zeros. Hours reached it first and independently. So a closed day is drawn as an absent row, never as a row of empty fields, because empty fields read as unfinished and this is finished. 2 · The holiday list genuinely beats the week, and precedence is invisible today. Both live in the same editor as two lists, and the only thing saying which wins is the sentence “these beat the week above”. Every layout here makes the override layer look like an override layer rather than a second list. Worth knowing while you judge: Scheduling deliberately has NO per-date exception and I shaped its cell so one could be added later. Hours already has them. So whatever wins here is the precedent for what Scheduling's eventually looks like — that is an argument for picking the one that reads best, not the one that is least work.
