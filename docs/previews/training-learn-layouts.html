Training · the Learn tab

Jose, 2026-10-01: “same on training, right now library is just showing everything the same, guides, and tests with no difference, im sure u can come up with a good overhaul”.

What is wrong today: the Library is five identical small white cards in one row, and the rest of a wide screen is empty. A guide and a test differ only by a few grey words (“screens” or “questions”), so a one-video introduction, a long guide and a 60-question test all look like the same thing. The test that follows a guide is a separate card with nothing joining them, and nothing says whether a test is open now or waits until its guide is read. Nothing shows where to pick up: the guide you are halfway through is the third card, with no next topic and no Continue. The cards count “screens” while the reader now says “topics”. A whole shelf is spent saying nothing is assigned, and there is no search or filter for when the library grows.

Every option keeps the rule Learn 1 was picked for in the first Training gallery: Assigned to you comes before the library and no filter can hide it. What each option replaces is Learn 1’s library shelf of equal cards. All of them also keep the place each item belongs to, and the reader rebuilt on A1 Tools’ layout, untouched: a guide still opens at its next topic, a test still opens the test screen, both inside Training with ← back. Every option adds a guide and a test that look different at a glance: a guide has the book icon, its topics and a progress bar, and is Completed when read; a test has the question icon, its questions, a score against its pass mark and the attempts left, says whether it is open now or waits for its guide, and is Passed or Not passed. It also adds the test joined to the guide it follows, where you left off by name with one Continue, “topics” in place of “screens”, and search. Chapters, topics, videos and the next topic’s name are counted from the topics GET /training/learn already sends with each guide, and a test names its guide in guide_id, so options 1, 2, 4 and 5 are client only.

1Continue first, then each guide joined to its test RecommendedClient only

Where you left off is the biggest thing on the page (the guide, the next topic by name, how far you are, one Continue), with Assigned to you beside it, so both things you owe sit above the fold. In the library each guide shares one card with its test, the guide on top with its bar and the test under it with its score, so the pair reads as two steps of one thing; a guide with no test, or a test with no guide, keeps the same card size and says so in words. Status chips and search cover a library that grows.

The library grouped into tracks (Technician, Dispatcher, Everyone), each drawn as its steps in order, so a new hire sees the whole path, the step they are on and what comes next, with their own role’s track first and a finished one marked Complete. A1 Tools grouped its training this way (each guide named the roles it was for), but the import reported those roles and did not keep them. Server: a track name and an order on each guide and test, a field to set them in Settings, and both sent by GET /training/learn.

What each option needs from the server

1 and 4Nothing. Optional: last_read_at on each guide (its progress row’s own updated_at) so Continue picks the guide opened most recently when two are half-read. Without it, Continue picks an assigned guide first, then the one furthest along.
2 and 5Nothing for what is drawn. A test’s panel lists only the last attempt (score, date, attempts left). Listing every attempt would need this person’s attempts sent with the test.
3 and 6A track: a name and an order on each guide and test, set in Settings › the guide or test, and sent by GET /training/learn. Putting “your role” first also needs a track to name the roles it is for. A1 Tools’ own role targeting, which the import printed and did not keep, could fill it in.
Any option“Passed, good until 9/30/2027” would need expires_on of the current pass, which the learner’s read does not send today (it sends the last score and date and how long a pass lasts). None of the six draws it.

Answer with one desktop number and one phone number, for example “1 and 4”. Names, places, dates and numbers are invented.
