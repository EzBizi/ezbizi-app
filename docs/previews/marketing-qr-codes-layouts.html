Marketing · QR Codes

Jose, 2026-10-05, through Marketing: a QR code printed for good on the company vehicles, so it has to be "1 consistent qr code" whose web address he can change in EzBizi, today a-1chimney.com and tomorrow a-1chimney.com/reviews, without reprinting. The printed image always encodes EzBizi's own short address (app.ezbizi.com/q/…), and that address forwards to wherever the code points now.

Data: nothing new. Marketing has built it: the codes with name, where each goes now, scans and last scanned; create, change, delete; and the image as SVG (for vehicle wraps) or PNG. A new tab, "QR Codes", beside Posts and Accounts. Changing, creating and deleting need Marketing's edit permission; without it the tab is read only.

1A card per code, its address changed right on the card Recommended

Each code is a card: the code itself (the real one, the same image that gets printed), its name, where it goes now with Change next to it, scans and the last scan, and the two downloads. Change opens a field on the card, with the line that matters: "The printed code stays the same; people who scan it go here instead." Delete is in the card's ⋮ menu and asks inside the card, in red: "Printed copies will stop working." New QR code is a side panel: a name and an address. Why: a business has a few of these, one per van or sign, so seeing each code next to where it goes is the whole job, and the main action is one tap on the card.
