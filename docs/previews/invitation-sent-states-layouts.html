The panel shown the one moment the raw token exists. Switch the state. Bounced is not knowable yet — SES event ingestion is being built — so every option needs somewhere to put it.

Revised 2026-09-14: “address refused” is no longer drawn as a send state, and HR is right that it should not be. The invitation is a PLATFORM send — Notification::route rather than MailDispatcher::asTenant — so it never produces CannotSendMail, the class that carries a human sentence. What it gets is a raw transport exception, and telling a rejected recipient from a dead connection would mean string-matching a vendor’s error text. The failure mode of guessing wrong is telling somebody to fix a perfectly good address — a confident sentence naming the wrong cause, which is the defect this whole entry exists to avoid. So the handoff failure says what it knows and no more, and the address is correctable in every state instead: the invitation keeps that address on record whatever happened, so the next invite goes to the same typo. “This address is wrong” gets said once there is a typed bounce event to say it with.

And correcting an address is a REISSUE, not a field edit — HR measured that too, and it changes the label rather than the layout. If the typo’d address belongs to a real person, that person is holding a working invitation to somebody else’s organization. Quietly repointing the row at the corrected address leaves their link alive while the screen says the problem is fixed — and that is worst in the SUCCESS state, which is exactly where this control is most useful. The semantics already exist and are tested: resend mints a new token and kills the old one. So the control reads as re-inviting, and says the current link stops working, because that is what happens.
