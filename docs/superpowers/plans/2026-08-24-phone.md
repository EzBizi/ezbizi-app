> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>

>
> **Do not touch Email files** except `RolesController` / `InboxAccess`-style nesting when Phone grants need the same editor. Off limits: mailbox readers, WatchMailboxes, `client/lib/screens/email/`. If a task seems to need those, the task is wrong — copy the *pattern*, not the file.

**Goal:** Replace the Phone coming-soon tab with the Twilio phone system in `docs/superpowers/specs/2026-08-24-phone-design.md`: org/company connections (BYO or EzBizi subaccount), numbers at org/company/franchise, role grants, TwiML flows, Voice JS softphone, SMS gated on 10DLC, Records, Settings.

**Architecture:** One `phone_connections` row per organization or company. Numbers resolve credentials by walking up (franchise → company → org) without inheriting lines. We emit TwiML; Twilio `<Dial>` rings at most ten Clients. Voice JS SDK tokens are minted per connection. Webhooks are public, authenticated by `X-Twilio-Signature` against **that** connection’s token. Audio stays on Twilio.

**Tech Stack:** Laravel 13 · PHP 8.4 · MySQL 8 (`ezbizi_testing`) · `twilio/sdk` · Flutter web + `@twilio/voice-sdk` via JS interop · ModuleRegistry · EventEmitter · FileStore · Refusal

**Spec:** `docs/superpowers/specs/2026-08-24-phone-design.md`  
**Layouts:** `docs/previews/phone-layouts.html` — Call **1**, Records **4**, Settings **6**, 375px stack **8**.

## Global Constraints

- Front door: `StartUp.md`. STATUS wins disagreements; this spec wins on Phone.
- TDD: red test first; delete the production line once and watch it fail; restore.
- User-facing sentences only. No class names, `::`, or “immutable.”
- No modals. 375px: one Call pane at a time, Back. Touch 44px.
- Colours from `client/lib/core/theme.dart`. No purple. No literal hex in widgets.
- Tab permission `phone.view`. Settings/buy/connect is `phone.edit`. Number grants compose with view (mailbox pattern).
- MySQL gate: `php artisan test` against a database whose name contains `testing`. Never assert JSON key order.
- Register server module and client screen in the same commit that removes Coming soon (`ClientModuleScreensTest`, `ComingSoonModulesTest`).
- Triggers: `isRaised: false` until `EventEmitter::emit('phone.…')` exists in `app/` outside `ModuleServiceProvider`; `ModuleRegistryTest` checks the claim against source.
- Subject of the module is **null** (call, SMS, and number — same as HR). Keys may be `phone.call.*`, `phone.sms.*`, `phone.voicemail.*`, `phone.number.*`.
- Bump `client/VERSION` and add a `VersionHistory` row in the **same** commit that ships UI.
- Secrets: encrypted column, `MasksSensitiveValues`, `mayReveal` false. Never in JSON, logs, or chat.
- Platform Twilio env names (never in git): `TWILIO_PLATFORM_ACCOUNT_SID`, `TWILIO_PLATFORM_API_KEY_SID`, `TWILIO_PLATFORM_API_SECRET`.
- No action that places a call or sends SMS from automations.
