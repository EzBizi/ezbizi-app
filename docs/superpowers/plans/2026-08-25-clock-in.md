# Clock in Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Do not deploy, `git push production`, or SSH.** Only when the owner says so in that session.
>
> **Stay off** Email, Phone, Inventory, Fleet, Inspection, Marketing except `/me`, the AppBar, `HrScreen`, `ModuleServiceProvider`, `SettingRegistry`, theme, and the roles catalogue — those already sit on the path.

**Goal:** Ship organization-gated Clock in: a top-bar punch button for roles that hold `time_clock.view`, and a one-day HR list for `hr.view`.

**Architecture:** `time_clock` is a grantable module that is **not** a sidebar tab (`sidebar: false`). The org setting `time_clock.enabled` (off by default) is the master switch. Shifts live in `time_clock_shifts` as UTC instants; `/me` carries the open shift so every device paints from the server; the HR day list buckets and formats in the current view’s timezone.

**Tech Stack:** Laravel 13 · PHP 8.4 · MySQL 8 (`ezbizi_testing`) · Flutter web · ModuleRegistry · SettingRegistry · SettingsResolver · ViewScope · EventEmitter · AuditLogger · ScopeReach

**Spec:** `docs/superpowers/specs/2026-08-25-clock-in-design.md`

## Global Constraints

- Front door: `StartUp.md`. If documents disagree, `docs/EZBIZI-STATUS.md` wins; this spec wins on Clock in.
- TDD: red test first; delete the production line once and watch it fail; restore.
- User-facing sentences name what happened and what to do. No class names, `::`, or “immutable.”
- No modal pop-ups. Chrome notice for punch failures.
- Client never sends a timestamp. Server `now()`, stored UTC.
- Device timezone is never read. “Today” is the view timezone from `ViewScope::settingsScope()`.
- `time_clock.view` must **not** imply `hr.view`. Clock in is not an `hr.*` action.
- Do not add `time_clock` to `moduleScreens` or `GlanceRegistry::ORDER`.
- MySQL gate: `php artisan test` against a database whose name contains `testing`.
- Dart tests from `client/`: `flutter test test/<file>.dart`. Bump `client/VERSION` and a `VersionHistory` row in the same commit that ships UI.
- Same deploy ships PHP and Flutter. Do not deploy from this plan.
- i18n: button, chip, empty sentence, timezone caption, **In**, refusals go through `UiStrings` / `ui_strings` (en + es). Roles labels come from the module registry.
