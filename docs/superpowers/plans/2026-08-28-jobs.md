# Jobs Module Build-Out — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grow Jobs from the Phase-2 vertical slice into a work order: service lines from the Services catalogue with a derived total, an assigned role, the person who did it, materials, photographs, the bound inspection, a schedule view, and a revenue figure that stops being wrong.

**Architecture:** Two nullable columns and one nullable timestamp on `jobs`, one new `job_lines` table holding service lines only, and one new organization setting. Materials, photographs and inspections are surfaced from wiring that already exists rather than built. The client gains a role column, a Work tab, three read-only tabs and a second view; the existing right-side panel stays the only detail surface.

**Tech Stack:** Laravel 12 / PHP 8.4, MySQL 8.4, Flutter (Dart), PHPUnit, `flutter test`.

**Spec:** `docs/superpowers/specs/2026-08-28-jobs-design.md` — read it before Task 1. The plan argues from the spec; where they disagree the spec wins.

## Global Constraints

- **Test database:** `DB_DATABASE=ezbizi_testing_jobs vendor/bin/phpunit` — **never** the shared `ezbizi_testing`. `RefreshDatabase` drops the schema and two sessions running at once destroy each other silently. `phpunit.xml:27` has no `force="true"`, so a real environment variable wins.
- **Exit 0 is not a pass.** Read the summary line's clauses. This repo has recorded a run that exited 0 while printing 3 failures and 17 errors.
- **Break every test on purpose once** before believing it. This repo has shipped tests that passed against the exact bug they claimed to catch.
- **Committing:** `git commit -F <msgfile> -- <exact/path>`. Options **before** the `--`, paths after. The index is shared across four-plus sessions and is usually loaded with other people's staged work; a plain `git commit` sweeps all of it. Never `git add -A`.
- **`client/VERSION`** is bumped once per release by whoever cuts it — **not** in these commits.
- **No modals, ever.** `showDialog` is not an option, including for "add a service". Use the right-side panel or an inline row.
- **375px must work.** Touch and pinch first-class.
- **Colours only from `client/lib/core/theme.dart`.** No literals.
- **Money:** integer minor units everywhere. Never divide by 100 in PHP.
- **Filing follows the view:** `franchisesInView` / `filingCompanyId`, never a `me.franchises` loop or `.first`.
- **Writes never dispatch.** `$this->events->emit(...)` inside the same `DB::transaction` as the record and its audit row.
- **Refusal sentences** come from `app/Support/Access/Refusal.php`. The client shows that sentence; it never writes a second copy.
- **Shared files** (`routes/api.php`, `app/Providers/ModuleServiceProvider.php`, `app/Support/Settings/SettingRegistry.php`): announce before editing, stage as a partial commit, never `git add` the whole file.
- Assert on values, never on the key order of anything read back from MySQL.

## Release Sequencing — EzBizi is in App Store review

**In force from 2026-08-28 until review clears.** Apple's reviewer runs a **frozen binary** — `client/VERSION` 0.0.0112, commit `8327833` — against **live production**. The .ipa cannot change; production can. A break is **invisible from our side**: no failed session to observe, just a rejection days later, and resubmitting resets the clock.

**Verified against the frozen tree, not inferred.** `git show 8327833:client/lib/screens/jobs_screen.dart` says exactly what the reviewer's client parses:

| Frozen code | What it binds |
|---|---|
| `:322` `job['amount'] as Map<String, dynamic>` | **Hard, non-nullable cast.** `amount` must keep arriving as a map on every job. Absent or null **throws** on the reviewer's job list. |
| `:357-358` `amount['display']`, `amount['currency']` | Both keys must keep arriving. |
| `:543` posts `'amount_minor': ?cents` | **`POST /jobs` must keep accepting `amount_minor`.** The reviewer's create form sends it. |
| `:693` `(c['owning_franchise'] as Map)['name']` | The **customer** payload the job form reads. `owning_franchise` must keep arriving as a non-null map. Adding nested keys is safe; making it conditional is not. |

**What this forbids, specifically — these are the tidy-ups this build invites:**

1. **Do not remove `amount_minor` from `JobsController::rules()`.** Once the total is derived it looks like dead input and the reflex is to delete it. The reviewer's create form posts it. Leave it accepted; `recomputeTotal()` overwrites it the moment a line exists, which is the correct behaviour anyway.
2. **Do not restructure the `amount` block in `present()`.** Keep `{minor, currency, display}` exactly. Add beside it, never reshape it.
3. **Do not make `owning_franchise` conditional** on the customer payload — a reasonable "only include it when set" change crashes the reviewer's job form. This binds Jobs even though the field is Customers'.
4. **Do not set or raise a minimum client version.** `EnforceMinimumClientVersion` can 426 every client from a database row with no deploy. Production has none set. The reflex after a wire change is to raise it — don't.

**Task ordering under the freeze:**

- **Tasks 1–5, 7–10 ship freely.** New tables, new fields, new endpoints, and all client work. The reviewer's client cannot call what it does not know about, and client-side changes never reach the reviewer at all — their client is the .ipa, not what we deploy. Task 2's backfill leaves every existing total **numerically identical**, so even the derived total is invisible to the frozen build until somebody edits a line, which the frozen build cannot do.
- **HOLD Task 6 (Revenue) until review clears.** It is the one task that changes numbers an existing response already returns, and its `needs_configuring` guard can flip a working dashboard into "Choose which of your job statuses count as earned" if an organization's migrated setting comes out empty. That is a visible functional regression on the reviewer's binary. Nothing else in this plan depends on Task 6, so holding it costs nothing.

**The general technique, which beats any rule written here:** the frozen tree is readable. Before changing any existing response, run `git show 8327833:<path>` and read what the reviewer's client actually parses. That is the only authority.

```php
<?php

namespace App\Support\Jobs;

use App\Models\Franchise;
use App\Models\Job;
use App\Support\Settings\SettingsResolver;

/**
 * Which job statuses mean the money is earned (spec §8.2).
 *
 * One place, because this answer is load-bearing twice: it decides WHICH jobs
 * count as revenue and — through the transition that stamps `earned_at` — WHEN
 * they count. It used to live in `user.preferences`, which made it a personal
 * opinion about a company fact; two people could disagree about whether a job
 * was revenue, and `earned_at` has room for only one answer.
 */
final class EarnedStatuses
{
    /** @return list<string> */
    public static function for(Franchise $scope): array
    {
        $chosen = app(SettingsResolver::class)->get('jobs.earned_statuses', $scope);

        if (! is_array($chosen)) {
            return [];
        }

        // Intersect with the vocabulary the organization actually publishes. A
        // renamed status must stop meaning earned rather than silently keeping
        // a value nothing can reach.
        $published = Job::allowedStatuses($scope);

        return array_values(array_intersect(
            array_filter($chosen, 'is_string'),
            $published,
        ));
    }

    public static function isEarned(string $status, Franchise $scope): bool
    {
        return in_array($status, self::for($scope), strict: true);
    }
}
```

use App\Models\User;

/**

 * organization setting (spec §8.2).

 * Nobody loses a choice they made — it stops being private to them. Where two
 * users in one organization disagree, the UNION is taken: under-counting
 * revenue is the worse error, and an organization can narrow it afterwards.

return new class extends Migration
{
    public function up(): void
    {
        $byOrg = [];

        User::query()->whereNotNull('preferences')->cursor()->each(function (User $user) use (&$byOrg) {
            foreach ((array) ($user->preferences['dashboard.glances'] ?? []) as $glance) {
                if (($glance['key'] ?? null) !== 'jobs') {
                    continue;

        }
    }

    public function down(): void
    {

    }

use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Schema;

/**
 * Jobs becomes a work order (spec §5, §7, §8.1).
 *
 * `job_lines` holds SERVICE lines only. Materials are read from
 * `inventory_issues.job_id` and carry no money at all (§9), so there is no
 * material line here and no cost anywhere on a job.
 */
return new class extends Migration
{
    public function up(): void
    {
        Schema::table('jobs', function (Blueprint $table) {
            // Whose trade this is. Roles are organization-global, so this is
            // scoped to the tenant rather than to the franchise.
            $table->foreignUuid('assigned_role_id')->nullable()->after('status')
                ->constrained('roles')->nullOnDelete();

            // Who actually did it. Personal data — see Job::retention().
            $table->foreignUuid('performed_by_user_id')->nullable()->after('assigned_role_id')
                ->constrained('users')->nullOnDelete();

            // When the money was earned. Revenue is reported against THIS, not
            // created_at: a job booked in June and finished in September is
            // September's revenue, and a closed month must stay closed (§8.1).
            $table->timestamp('earned_at')->nullable()->after('scheduled_for');

            $table->index(['organization_id', 'assigned_role_id']);
            $table->index(['organization_id', 'earned_at']);
        });

        Schema::create('job_lines', function (Blueprint $table) {
            $table->uuid('id')->primary();
            $table->foreignUuid('organization_id')->constrained()->cascadeOnDelete();

            // Nulls if the catalogue row is later removed. The LINE survives,
            // because the work was done whatever happened to the catalogue.

            // Snapshots, not lookups. A catalogue price is a current fact; a job

            $table->string('name', 191);
            $table->unsignedBigInteger('unit_price_minor')->default(0);
            $table->unsignedInteger('qty')->default(1);
            $table->unsignedBigInteger('amount_minor')->default(0);

            $table->unsignedInteger('position')->default(0);
            $table->timestamps();

            $table->index(['organization_id', 'job_id']);
        });

        // Every job that already has a typed total keeps it, as ONE line that
        // says what it is. Not silently dressed up as a service it never was.
        DB::table('jobs')
            ->whereNotNull('amount_minor')
            ->where('amount_minor', '>', 0)
            ->orderBy('id')
            ->chunkById(500, function ($jobs) {
                $rows = [];

                foreach ($jobs as $job) {
                    $rows[] = [
                        'id'               => (string) Str::uuid(),
                        'organization_id'  => $job->organization_id,
                        'job_id'           => $job->id,
                        'service_id'       => null,
                        'name'             => 'Job total (entered before itemisation)',
                        'unit_price_minor' => $job->amount_minor,
                        'qty'              => 1,
                        'amount_minor'     => $job->amount_minor,
                        'position'         => 0,
                        'created_at'       => now(),
                        'updated_at'       => now(),
                    ];
                }

                if ($rows !== []) {
                    DB::table('job_lines')->insert($rows);
                }
            });
    }

    public function down(): void
    {

        Schema::table('jobs', function (Blueprint $table) {

            $table->dropConstrainedForeignId('performed_by_user_id');

use App\Models\Concerns\BelongsToTenant;
use App\Support\Privacy\RetentionPolicy;
use App\Support\Privacy\StatesRetention;
use Illuminate\Database\Eloquent\Attributes\Fillable;
use Illuminate\Database\Eloquent\Concerns\HasUuids;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Relations\BelongsTo;

/**
 * One line of work on a job (spec §7).
 *
 * `name` and `unit_price_minor` are SNAPSHOTS taken when the line was added,
 * not lookups through `service_id`. The catalogue is a current fact and a job
 * is a historical one — a price raised in September must not rewrite what a
 * job in August came to, and the Revenue widget must not report a past month
 * differently each time it is opened.
 */
#[Fillable([
    'organization_id', 'service_id', 'name', 'unit_price_minor', 'qty',
    'amount_minor', 'position',
])]
class JobLine extends Model implements StatesRetention
{
    use BelongsToTenant;
    use HasUuids;

    public static function retention(): RetentionPolicy
    {
        return RetentionPolicy::withParent(
            'A line of work hangs off the job. It names a service and a price and '
            .'holds no information about any person. Removing the job takes it.'
        );
    }

    protected function casts(): array
    {
        return [
            'unit_price_minor' => 'integer',
            'qty'              => 'integer',
            'amount_minor'     => 'integer',
            'position'         => 'integer',
        ];
    }

    public function job(): BelongsTo
    {
        return $this->belongsTo(Job::class);
    }

    public function service(): BelongsTo
    {
        return $this->belongsTo(Service::class);
    }
}

<?php

namespace App\Http\Controllers\Api;

use App\Models\Job;
use App\Models\JobLine;
use App\Models\Service;
use App\Support\Audit\AuditLogger;
use App\Support\Automations\EventEmitter;
use App\Support\Tenancy\TenantContext;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\DB;
use Illuminate\Validation\Rule;
use Symfony\Component\HttpFoundation\Response;

/**
 * The work on a job (spec §7).
 *
 * A line is created FROM a service and then stops depending on it: name and
 * price are copied onto the row. Editing the catalogue afterwards is not an
 * edit to any job.
 *
 * There is no material line here. Materials are read from
 * `inventory_issues.job_id` and carry no money (§9), so nothing on a job holds
 * a cost and no total over jobs can leak one.
 */
class JobLinesController extends Controller
{
    public function __construct(
        private readonly AuditLogger $audit,
        private readonly EventEmitter $events,
        private readonly TenantContext $tenant,
    ) {}

    /** POST /api/v1/jobs/{job}/lines */
    public function store(Request $request, Job $job): JsonResponse
    {
        $this->authorize('update', $job);

        $input = $request->validate([
            'service_id' => [
                'required', 'uuid',
                Rule::exists('services', 'id')->where('organization_id', $this->tenant->idOrFail()),
            ],
            'qty' => ['required', 'integer', 'min:1', 'max:100000'],
        ]);

        $service = Service::findOrFail($input['service_id']);

        $line = DB::transaction(function () use ($job, $service, $input) {
            $unit = (int) ($service->price_minor ?? 0);

            $line = $job->lines()->create([
                'organization_id'  => $job->organization_id,
                'service_id'       => $service->getKey(),
                'name'             => $service->name,
                'unit_price_minor' => $unit,
                'qty'              => $input['qty'],
                'amount_minor'     => $unit * $input['qty'],
                'position'         => (int) $job->lines()->max('position') + 1,
            ]);

            $job->recomputeTotal();

            $this->audit->log('job.line_added', $job, metadata: [
                'name'  => $line->name,
                'total' => $job->fresh()->amount_minor,
            ]);

            // A line change is a change to the job. No per-line trigger: it
            // would fire three times for one edit and no rule hangs off it.
            $this->events->emit('job.updated', $job, [
                'after' => ['amount_minor' => $job->fresh()->amount_minor],
            ]);

            return $line;
        });

        return response()->json(['data' => $this->present($line)], Response::HTTP_CREATED);
    }

    /** PATCH /api/v1/jobs/{job}/lines/{line} */
    public function update(Request $request, Job $job, JobLine $line): JsonResponse
    {
        $this->authorize('update', $job);
        abort_unless($line->job_id === $job->getKey(), Response::HTTP_NOT_FOUND);

        $input = $request->validate([
            'qty' => ['required', 'integer', 'min:1', 'max:100000'],
        ]);

        DB::transaction(function () use ($job, $line, $input) {
            $line->forceFill([
                'qty'          => $input['qty'],
                'amount_minor' => $line->unit_price_minor * $input['qty'],
            ])->save();

            $job->recomputeTotal();

            $this->audit->log('job.line_changed', $job, metadata: ['name' => $line->name]);
            $this->events->emit('job.updated', $job, [
                'after' => ['amount_minor' => $job->fresh()->amount_minor],
            ]);
        });

        return response()->json(['data' => $this->present($line->fresh())]);
    }

    /** DELETE /api/v1/jobs/{job}/lines/{line} */
    public function destroy(Job $job, JobLine $line): JsonResponse
    {
        $this->authorize('update', $job);
        abort_unless($line->job_id === $job->getKey(), Response::HTTP_NOT_FOUND);

        DB::transaction(function () use ($job, $line) {
            $this->audit->log('job.line_removed', $job, metadata: ['name' => $line->name]);
            $line->delete();
            $job->recomputeTotal();
            $this->events->emit('job.updated', $job, [
                'after' => ['amount_minor' => $job->fresh()->amount_minor],
            ]);
        });

        return response()->json(['message' => 'Line removed.']);
    }

    /** @return array<string, mixed> */
    private function present(JobLine $line): array
    {
        return [
            'id'               => $line->id,
            'service_id'       => $line->service_id,
            'name'             => $line->name,
            'unit_price_minor' => $line->unit_price_minor,
            'qty'              => $line->qty,
            'amount_minor'     => $line->amount_minor,
            'position'         => $line->position,
        ];
    }
}
